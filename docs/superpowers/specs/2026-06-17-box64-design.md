# Box-64 — Custom Model Car Box E-commerce Platform
**Spec date:** 2026-06-17  
**Status:** Approved for implementation planning

---

## 1. Product Overview

A web platform to sell custom packaging boxes for 1:64 scale diecast model cars (MiniGT / Poprace sizes). Two primary business modes: (A) sell pre-designed boxes from a catalog, and (B) let customers design their own box using uploaded car photos and a live preview tool.

**Product types:**
- **Box Custom** — customer designs their own box using the designer tool, orders 1+ copies
- **Box Catalog** — pre-made designs available in the shop
- **Card Custom** — custom display card (future scope, not phase 1)
- **Accessories 1/64** — small add-ons (stands, cases) — simple product listing, no designer

**Business model:** Print & ship. Customer designs online → admin prints → ships.

## 4. Box Designer Tool

### 4-Step Wizard

**Step 1 — Upload car image**
- Drag-and-drop or file picker
- Client-side crop via Canvas API (`drawImage` + user-draggable crop rect) — no extra library
- Stores as blob URL in Zustand; uploads to Supabase Storage on checkout

**Step 2 — Car info**
- Car name (text field, rendered on canvas)
- Specs line (scale, color, edition)
- Warning / fine print text (optional, pre-filled)

**Step 3 — Visual options**
- Logo variant: MiniGT / Poprace / Custom (upload)
- Color pickers per component:
  - Background color
  - Accent stripe color
  - Text color
  - Logo tint (if using preset)
- Select box size: MiniGT (~120×55×40mm) or Poprace (~115×60×45mm)

**Step 4 — Review & add to cart**
- Final isometric preview
- Quantity selector (1–100)
- Price shown

### Designer Layout

Split panel: Form (left, 40%) + Preview (right, 60%)

Preview shows the isometric CSS box in real-time. Each face is a `<canvas>` element that redraws on any state change via `requestAnimationFrame`.

### Canvas Architecture

Each box face = independent `<canvas>`:
- `canvas-front` — main face (orange in template): car image + car name + logo + accent stripes
- `canvas-top` — top strip (green): car name abbreviated
- `canvas-side` — right side (blue): car name vertical

All text drawn via `ctx.fillText()` — never DOM text nodes. This solves brand protection automatically (canvas output is a rasterized bitmap, not indexable text).

### Box Face Coordinates (from `demo-area.svg`)

ViewBox: `841.89 × 595.28` (A4 landscape)

| Face | Color code | SVG coords | Role |
|---|---|---|---|
| Green | #71bf4e | x=277.88 y=184.25 w=286.22 h=130.12 | Left side face |
| Orange | #f99c1c | x=277.88 y=314.65 w=286.22 h=130.12 | **Main face (FRONT)** |
| Pink L | #b4519e | x=147.76 y=314.65 w=130.12 h=130.12 | Front lid |
| Pink R | #b4519e | x=564.10 y=314.65 w=130.12 h=130.12 | Back lid |
| Blue T | #478ecc | x=277.88 y=54.13 w=286.22 h=130.12 | Bottom face |
| Blue B | #478ecc | x=277.88 y=445.04 w=286.22 h=130.12 | Right side face |

Main face ratio: 286.22 × 130.12 ≈ **2.2:1 (width:height)**. Lids are square 130.12 × 130.12.

## 5. Post-Payment Box Fold Animation

Triggered when payment is confirmed (before showing order summary).

**Sequence:**
1. Flat cross layout fades in (color-coded faces, like the SVG template)
2. "Gấp hộp…" label appears
3. CSS transitions (Framer Motion spring physics) fold each face:
   - Green left face: `rotateY(90deg)` pivot on right edge → folds toward back
   - Blue bottom: `rotateY(-90deg)` pivot on left edge → folds toward front
   - Blue top: `rotateX(180deg)` → folds flat (bottom face)
   - Pink lids: `rotateY(90deg)` inward → close the ends
4. All faces meet → assembled isometric view animates into place
5. Fade to order confirmation summary

Stagger delays: left 0ms → right 200ms → bottom 400ms → lids 600ms → assemble 900ms.

Implementation: CSS `transform-style: preserve-3d` + `perspective` + Framer Motion for spring easing.

## 6. Shop & E-commerce

### Product Listing

- Filter tabs: All / Box Custom / Box Catalog / Pre-order / Sale
- Sort: Newest / Price / Popular
- Countdown timer on card image (bottom-right, blur backdrop) — for sale + pre-order items
- Card tinting by status

### Cart

- Slide-in drawer from right (Framer Motion)
- Shows thumbnail, name, qty stepper, subtotal
- Upsell bar: amber banner at top of drawer showing "Add X more boxes for free shipping" (threshold: 5 boxes)
- Checkout button → checkout page

### Checkout Flow

1. **Shipping address**
   - Phone number field → OTP via Supabase Auth
   - After OTP verified: show saved addresses (if any) OR new address form
   - Country auto-detected (default Vietnam)
2. **Shipping method** — fixed options per country
3. **Payment**
   - Vietnam: VNPay or MoMo (radio buttons)
   - Other countries: PayPal (shown automatically based on selected country)
4. **Review & confirm** → redirect to payment gateway → return to post-payment animation

### Phone-Based Address Book

- No forced account creation
- Phone OTP creates/resumes a Supabase Auth session
- On checkout, if session has saved addresses → pre-fill form
- User can save address after completing first order

## 7. Promotions Engine

Single promotion engine powering both sale discounts and pre-orders.

**Rules:**
- Only 1 promotion applies per cart (highest discount wins, or admin-configured priority)
- Promotions can be product-level or sitewide
- Countdown timer syncs to Supabase server time (not `Date.now()`) — accurate across SEA timezones

**Promotion types:**

| Type | Label | Timer behavior |
|---|---|---|
| Sale | "SALE — X% OFF" | Counts down to end of sale |
| Pre-order | "PRE-ORDER" | Counts down to shipping date |
| Flash sale | "FLASH SALE" | Short window, prominent red badge |

**Timer display:** Small pill badge overlaid on card image (bottom-right corner), blur backdrop, white text. On product detail page: larger display with days/hours/mins/secs.

## 8. Brand Protection

All brand names (MiniGT, Poprace, etc.) are rendered exclusively via Canvas API `ctx.fillText()`, never as DOM text nodes. This means:
- Search crawlers cannot index brand name mentions
- No DOM text = no trademark-related indexing risk
- Zero extra implementation cost — canvas rendering is already required for the designer tool

## 9. PDF Export (Print-Ready)

When a customer completes a box design and pays, the system generates a print-ready PDF:

- **Trigger:** Supabase Edge Function (Puppeteer)
- **Source:** Flat HTML template with all 6 face canvases rendered server-side
- **Output specs:** A4 landscape, 300dpi equivalent, 3mm bleed marks, cut lines
- **Storage:** PDF saved to Supabase Storage, linked to order record
- **Admin access:** PDF download link in admin order detail panel

Client-side jsPDF is not used — quality is insufficient for print production.

## 10. Order Tracking

Phone-number-based lookup (no login required):
1. Customer enters phone number on `/track` page
2. System sends OTP (or uses active session)
3. Shows list of orders linked to that phone number
4. Each order shows: status (Pending → Printing → Shipped → Delivered), tracking number if shipped

---

## 11. Admin Panel

Full admin at `/admin` (protected by Supabase RLS + admin role).

**Sections:**
- **Orders** — list, filter by status, update status, download PDF, add tracking number
- **Products** — create/edit catalog items, set prices, upload images
- **Designer Templates** — manage base templates for Box Custom (logo variants, default colors)
- **Promotions** — create/edit/end promotions, set countdown end dates
- **Reports** — revenue by period, top products, order volume
- **Settings** — shipping zones, payment config, upsell threshold
